# Introduction (简介)

Cube 是一个由开源语义层（Semantic Layer）驱动的商业智能（BI）平台。它利用 AI 代理构建数据模型，并使数据消费者能够进行分析。

## 核心定位
- **赋能不同角色**：
  - **数据工程师**：借助 AI 辅助快速构建和维护语义层。
  - **数据分析师**：在 AI 协助下进行深度数据探索和模式识别。
  - **业务用户**：直接使用 Cube 自动构建和维护的工作簿及仪表板。

## 核心支柱 (Four Pillars)

### 1. 数据建模 (Data Modeling)
- **重点/约束**：
  - **知识图谱**：为 AI 提供理解业务的上下文。
  - **代码优先 (Code-first)**：使用 YAML 或 JavaScript 定义模型，必须通过版本控制（Git）管理。
  - **以数据集为中心**：采用维度建模思想。
  - **Cube 对象**：代表业务实体（如客户、订单），定义度量（Measures）、维度（Dimensions）及关系。
  - **View 对象**：位于 Cube 之上的展示层，作为最终交付给 AI 或 BI 的数据集。

### 2. 访问控制 (Access Control)
- **重点/约束**：
  - **一致性安全性**：确保 AI 代理与人类用户遵循相同的安全策略。
  - **集中治理**：所有访问必须经过语义层检查点。
  - **定义方式**：通过 Python 或 JavaScript 定义复杂的访问规则（行级安全、列级限制、数据脱敏）。

### 3. 缓存 (Caching)
- **重点/约束**：
  - **预聚合 (Pre-aggregations)**：核心性能优化框架。
  - **Cube Store**：专门的分布式缓存引擎（支持 S3 等存储）。
  - **聚合识别 (Aggregate Awareness)**：查询引擎自动判断是否可使用预聚合表，以降低延迟和仓库成本。

### 4. API 接口 (APIs)
- **重点/约束**：
  - **标准协议**：支持 REST、GraphQL 和 SQL（Postgres 兼容）。
  - **语义 SQL**：扩展了 `MEASURE` 函数，允许 AI 在治理范围内进行即席计算。
  - **元数据自省 (Meta API)**：AI 代理发现度量、维度和关系的必备接口。

## 核心差异点
- **语义 SQL**：AI 不直接查询数据库，而是通过语义层代理，确保查询的确定性和安全性。
- **防止错误查询**：语义层作为护栏，验证所有请求，防止错误 SQL 到达数据仓库。
